# Text Chat Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for implementation, with independent test authoring and final code review. Track steps below.

**Goal:** Авторизованный пользователь создаёт свои диалоги, отправляет сообщения и получает сохранённую историю с ответом заглушки.

**Architecture:** Отдельный модуль `modules/dialogues` использует существующие `Base`, `CurrentUser` и `SessionDep`. В общих файлах разрешены только добавления для подключения маршрутов и моделей. Сообщение пользователя и ответ сохраняются одной транзакцией.

**Tech Stack:** Python 3.12+, FastAPI, Pydantic v2, async SQLAlchemy, существующая SQLite, pytest/TestClient.

**Spec:** Задание пользователя в этой сессии: создание диалога, отправка/сохранение сообщения, история, фиксированный ответ вместо ИИ, доступ только к собственным диалогам. Интеграция разрешена без изменения чужой логики. Основа схемы — `docs/architecture/data-model.md`.

## Global Constraints

- Код чата находится в `backend/src/linguabot/modules/dialogues/`.
- Не менять фронтенд, авторизацию, пользовательскую модель или зависимости проекта.
- Из существующего кода дополнить только `api/v1/router.py` и `db/session.py`.
- Не создавать отдельное приложение/базу для чата, не изменять существующие таблицы.
- Выполнять постепенные коммиты по завершённым проверенным этапам, как дополнительно запросил пользователь; не выполнять push.
- Работать в текущем проекте, как запрошено пользователем; тесты запускать на отдельной SQLite, без записей в `linguabot.db`.

## Decisions

- `POST /api/v1/dialogues`: `title` (1–160 символов, по умолчанию `Новый диалог`), `scenario` (1–64, по умолчанию `free_chat`); ответ 201 с диалогом.
- `GET /api/v1/dialogues`: список своих диалогов, новые ID сначала.
- `POST /api/v1/dialogues/{id}/messages`: `content` (1–4000 символов после удаления внешних пробелов); ответ 201 с `user_message` и `assistant_message`.
- `GET /api/v1/dialogues/{id}/messages`: история в порядке ID по возрастанию.
- Списки принимают `limit` (1–100, по умолчанию 100) и `offset` (от 0).
- ID диалога ограничен диапазоном 1–2147483647 для совместимости с SQLAlchemy Integer в PostgreSQL; слишком большой ID возвращает 422.
- Текст заглушки: `Спасибо за сообщение! Давай продолжим практику.`
- Владелец и роль сообщения задаются сервером; неизвестные поля тела запроса запрещены.
- Без авторизации — 401; чужой или отсутствующий диалог — одинаковая 404 с кодом `not_found`.
- `Dialogue`: id, user_id, title, scenario, status=active, created_at, updated_at.
- `Message`: id, dialogue_id, role, content, correction (nullable), created_at.
- `language_id` отложен: таблицы languages ещё нет, её создание выходит за задание. Ссылка на отсутствующую таблицу сломала бы запуск.
- Авторизация уже начинает транзакцию общей сессии: не вызывать вложенный `session.begin()`, выполнять один commit с rollback при ошибке.
- Добавление сообщений явно обновляет updated_at диалога.

## Review Focus

- Чужой ID не открывает историю и не позволяет записать сообщения.
- Пустой/пробельный/слишком длинный текст не попадает в базу.
- Повторное открытие клиента получает оба сохранённых сообщения, а не память процесса.
- Если сохранение ответа не удалось, сообщение пользователя также не сохраняется.
- Подключение новых моделей работает на чистой базе и не ломает существующую авторизацию.
