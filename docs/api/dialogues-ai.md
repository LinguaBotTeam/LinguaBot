# API диалогов с ИИ

Все операции требуют `Authorization: Bearer <access_token>`. Существующие поля и маршруты сохранены; схема БД не меняется.

Backend поддерживает локальную Ollama и Cloudflare Workers AI. Провайдер выбирается явно через `LLM_PROVIDER`; по умолчанию используется Ollama. Контракт HTTP API, проверка владельца, история и сохранение сообщений одинаковы для обоих вариантов.

| Метод и путь | Результат |
| --- | --- |
| `POST /api/v1/dialogues` | 201, новый личный диалог; необязательные `title` и `scenario` |
| `GET /api/v1/dialogues` | 200, свои диалоги, новые ID сначала |
| `POST /api/v1/dialogues/{id}/messages` | 201, сохранённая пара сообщений после успешного ответа ИИ |
| `GET /api/v1/dialogues/{id}/messages` | 200, история своего диалога, старые ID сначала |

Списки принимают `limit` 1–100 (по умолчанию 100) и `offset` от 0. Диалог содержит `id`, `title`, `scenario`, `status`, `created_at`, `updated_at`. Сообщение содержит `id`, `dialogue_id`, `role`, `content`, `correction`, `created_at`. Диапазон ID: 1–2147483647. Длины строк: `title` 1–160, `scenario` 1–64, `content` 1–4000 символов; внешние пробелы удаляются, неизвестные поля запрещены. Владелец и роли задаются сервером.

## Сценарий и уровень

При создании укажи `introductions` («Знакомство»), `cafe` («Кафе») или `shop` («Магазин»). По умолчанию используется `free_chat`. Неизвестные названия продолжают храниться и читаться, но получают общий безопасный промпт. Реплики партнёра должны быть на английском. Для предложенного исправления сервер формирует русское описание точных замен, добавлений и удалений.

Читается последний результат теста текущего пользователя. Корректный CEFR A1–C2 имеет приоритет; также поддерживаются уровни `beginner` → A1, `intermediate` → B1, `advanced` → C1. Регистр и внешние пробелы нормализуются. При отсутствии поддерживаемого результата используется A1. Assessment работает без изменений.

Пример запроса:

```json
{"content": "I is hungry."}
```

Сокращённый пример пары (фактический ответ также включает ID и время):

```json
{
  "user_message": {
    "role": "user",
    "content": "I is hungry.",
    "correction": "Предлагаемое исправление: \"I am hungry.\"\nИзменения:\n1. Заменено \"is\" на \"am\"."
  },
  "assistant_message": {
    "role": "assistant",
    "content": "What would you like to eat?",
    "correction": null
  }
}
```

Это иллюстрация формата, а не гарантированный ответ модели. При корректном сообщении `user_message.correction` должен быть `null`. Исправление хранится на сообщении пользователя и возвращается в истории.

Публичный интерфейс адаптера остаётся `LanguageModel.generate(messages) -> ModelReply(reply, correction)`. Оба адаптера используют одну строгую внутреннюю схему: `reply` и обязательный `corrected_text`, полностью исправленный текущий текст либо `null`. Непустые строки ограничены 4000 символами; лишние поля запрещены. Промпт требует английский язык, но проверка JSON сама по себе не подтверждает язык и правильность текста. Поле `corrected_text` не добавляется в HTTP API или БД. Совпадающий с исходным текст также преобразуется в отсутствие исправления.

`build_correction` из `ai/feedback.py` сравнивает исходную и предложенную фразы и строит `correction` на русском для обоих провайдеров. В нём приводятся полная предлагаемая фраза и все изменения, включая пробелы и знаки препинания. Свободное объяснение грамматического правила от модели не принимается. Такой способ исключает противоречие между описанной заменой и показанной исправленной фразой, но не доказывает правильность самого предложения модели. Это описание того, **что** изменено; подробного объяснения, **почему** действует грамматическое правило, пока нет. Если полное описание превышает 3000 символов, ход завершается ошибкой 502 без обрезанного исправления и без записи сообщений.

## Контекст и запись

Доступ проверяется до чтения истории и assessment, создания клиента и генерации. Модель получает доверенные инструкции, CEFR, до 12 последних сообщений выбранного диалога и текущий текст. Бюджет истории — 4000 байт UTF-8 текста; старые сообщения исключаются целиком, сохраняется хронологический суффикс. Текущий текст не обрезается. Полная история API продолжает использовать прежние страницы.

Поля аккаунта/профиля, полный результат теста и другие диалоги в промпт не входят. Реплики остаются недоверенным текстом, в котором сам пользователь может написать личные сведения. Инструментов и доступа к файлам у модели нет.

При `LLM_PROVIDER=cloudflare` этот контекст и текущая реплика отправляются внешнему обработчику Cloudflare по HTTPS. Исключение полей профиля не обезличивает текст, введённый пользователем. Перед использованием облачного провайдера нужно учитывать эту передачу данных.

Пока модель отвечает, сервис не выполняет запись. Валидный ответ сохраняет обе реплики и `updated_at` одним commit. Ошибка генерации, некорректный ответ или ошибка записи не оставляют половины хода. Молчаливой замены ответа заглушкой нет.

## Ошибки

```json
{"error": {"code": "service_unavailable", "message": "Модель ИИ временно недоступна", "field": null}}
```

| Статус | Код | Причина |
| --- | --- | --- |
| 401 | `unauthorized` | Нет действующего токена |
| 404 | `not_found` | Диалог отсутствует или принадлежит другому пользователю |
| 409 | `conflict` | Уже готовится ответ в тот же диалог; повтори после завершения хода |
| 422 | `validation_error` | Неверный запрос, ID или параметры страницы |
| 502 | `bad_gateway` | Ответ модели пустой, некорректный, незавершённый или не соответствует JSON-контракту |
| 503 | `service_unavailable` | Провайдер недоступен, истёк тайм-аут, неверны настройки, отклонена авторизация Cloudflare или исчерпана облачная квота |

Ошибка не раскрывает тело ответа провайдера и внутренние детали. При 502/503 сообщения не сохраняются и время диалога не меняется. Историю можно читать. Повторный запрос после ошибки — новый ход.

Облачные HTTP-ошибки, в том числе 401/403/429, становятся 503 этого API. Ошибочный ответ успешного HTTP-вызова, например незавершённый JSON или неверная схема, становится 502. Сервис не повторяет вызов и не меняет провайдера автоматически; системные HTTP-прокси и редиректы отключены.

## Локальная конфигурация

Запускай backend одним worker: защита от пересекающихся ходов хранится в памяти одного процесса. Она не координирует несколько процессов или серверов. Другие диалоги могут обрабатываться независимо. Распределённая координация потребуется перед масштабированием.

Backend читает настройки из окружения или личного `.env` в каталоге `backend`. Образец находится в `backend/.env.example`. `LLM_PROVIDER=ollama` выбирает локальную модель, `LLM_PROVIDER=cloudflare` выбирает Workers AI. Другие значения недопустимы и приводят к 503 при генерации. Настройки выбранного провайдера проверяются при создании клиента. Переключение выполняется настройкой backend, без изменения публичного API.

### Ollama

| Настройка | По умолчанию | Ограничение |
| --- | --- | --- |
| `LLM_BASE_URL` | `http://127.0.0.1:11434` | Только HTTP loopback, без учётных данных и дополнительных компонентов URL |
| `LLM_MODEL` | `qwen3:4b-instruct-2507-q4_K_M` | Локальный тег; облачная маршрутизация запрещена |
| `LLM_TIMEOUT_SECONDS` | 120 | Больше 0, до 300 секунд |
| `LLM_CONTEXT_TOKENS` | 4096 | 1024–8192 токенов |
| `LLM_MAX_OUTPUT_TOKENS` | 384 | 1–1024 токена |

Эти параметры `LLM_*` относятся к Ollama и сохраняют прежние значения. Настрой отдельно окружение процесса Ollama с `OLLAMA_NO_CLOUD=1`: строка только в backend `.env` не настраивает уже запущенный Ollama. Модель должна быть заранее скачана; автоматического скачивания и облачного fallback нет.

### Cloudflare Workers AI

Сначала проверь в нужном аккаунте Cloudflare, что используется **Workers Free**. Только после этого заполни `CLOUDFLARE_ACCOUNT_ID` и `CLOUDFLARE_API_TOKEN` в личном `.env` и задай `LLM_PROVIDER=cloudflare`. Account ID состоит из 32 шестнадцатеричных символов. Для токена нужны права Workers AI Read и Edit, ограниченные нужным аккаунтом; используй официальный шаблон Workers AI API Token. Токен хранится только на backend, не попадает во frontend и не добавляется в Git. [Настройка REST API](https://developers.cloudflare.com/workers-ai/get-started/rest-api/).

| Настройка | По умолчанию | Ограничение |
| --- | --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | Нет | Обязательны 32 шестнадцатеричных символа |
| `CLOUDFLARE_API_TOKEN` | Нет | Обязателен непустой токен для HTTP-заголовка, до 4096 символов |
| `CLOUDFLARE_MODEL` | `@cf/meta/llama-3.3-70b-instruct-fp8-fast` | Разрешена только эта модель |
| `CLOUDFLARE_TIMEOUT_SECONDS` | 60 | Больше 0, до 120 секунд |
| `CLOUDFLARE_MAX_OUTPUT_TOKENS` | 512 | 1–1024 токена |

Адаптер делает один POST в `https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai/run/@cf/meta/llama-3.3-70b-instruct-fp8-fast`. Используются сообщения с ролями `system`, `user`, `assistant`, `temperature=0.3`, `stream=false` и JSON Mode с общей схемой `reply`/`corrected_text`. Внешний URL и модель фиксированы кодом. Автоматических повторов, переходов по редиректу, системных HTTP-прокси, AI Gateway и запасного провайдера нет. Cloudflare предупреждает, что JSON Mode не гарантирует соблюдение схемы во всех случаях; ответ всё равно проверяется на backend. [Модель](https://developers.cloudflare.com/workers-ai/models/llama-3.3-70b-instruct-fp8-fast/), [JSON Mode](https://developers.cloudflare.com/workers-ai/features/json-mode/).

Workers Free даёт общую для аккаунта квоту 10 000 нейронов в сутки. После её исчерпания Cloudflare отклоняет запросы; сброс происходит в 00:00 UTC. Это квота всех пользователей и приложений аккаунта, а не отдельный лимит на каждого пользователя LinguaBot. Длинные сообщения и история быстрее расходуют её; число доступных ходов и скорость не гарантированы. Код 429 с внутренним кодом 3036 означает исчерпание суточной квоты, 429/3040 означает временную нехватку мощности. В обоих случаях API возвращает 503 без сохранения хода. [Квоты и оплата](https://developers.cloudflare.com/workers-ai/platform/pricing/), [ошибки Workers AI](https://developers.cloudflare.com/workers-ai/platform/errors/).

Код не проверяет тариф аккаунта и не может подтвердить бесплатность произвольного API-токена. На Workers Paid использование сверх бесплатной квоты оплачивается, даже с той же моделью. Для этой конфигурации не подключай Workers Paid, предоплаченные кредиты, AI Gateway или платные модели. Ограничение токенов сдерживает расход квоты, но не заменяет проверку тарифа. Платного переключения или автоматического fallback в приложении нет.

При использовании облачной модели: **Built with Llama**. Модель распространяется по [Llama 3.3 Community License](https://github.com/meta-llama/llama-models/blob/main/models/llama3_3/LICENSE) с [Acceptable Use Policy](https://github.com/meta-llama/llama-models/blob/main/models/llama3_3/USE_POLICY.md). В [карточке издателя](https://huggingface.co/meta-llama/Llama-3.3-70B-Instruct) предусмотрены ассистентские диалоги, коммерческое и исследовательское использование; учебное применение не отменяет условий лицензии и правил использования.

### Запуск backend

Запуск из `backend`:

```powershell
.\.venv\Scripts\python.exe -m uvicorn linguabot.main:app --app-dir src --workers 1
```

Swagger находится на `http://127.0.0.1:8000/docs`. Шаги входа и команда автономных тестов приведены в [README модуля](../../backend/src/linguabot/modules/dialogues/README.md). Автономные тесты заменяют внешнюю границу модели и используют отдельную SQLite; Ollama и учётные данные Cloudflare для них не нужны. Они не подтверждают доступность облачной модели, тариф аккаунта или качество реальной генерации.

## Границы проверки качества

Для новой облачной интеграции аккаунт и учётные данные пока не настроены. Реальных вызовов Cloudflare, проверки его Free-тарифа и оценки облачных ответов не проводилось. Следующие результаты относятся только к ранее завершённой проверке локальной Ollama; повторным запуском Cloudflare они не являются.

На CPU генерация может быть медленной и ограничивается тайм-аутом. В проверенной конфигурации запрос без истории занимал около 500 входных токенов; точное число зависит от темы и текста. Даже допустимого малого контекста может не хватить для длинного сообщения и истории: фактическая токенизация зависит от модели. Для проверенной конфигурации использовалось 4096 токенов.

С текущим внутренним контрактом выполнена серия из 30 заранее заданных синтетических запросов к настоящей локальной модели через адаптер: 21 отдельный пример и три диалога по три хода. Проверены три темы, семь ошибочных фраз и корректные варианты, факты из истории, уровни A1/C1 и попытки изменить инструкции. Во всех 30 случаях результат исправления или его отсутствие совпал с ожидаемым; ложных исправлений в этой серии не обнаружено. Первый запрос занял около 38 секунд с загрузкой модели, последующие — примерно 3–15 секунд на CPU. Это результат одного ограниченного набора, а не гарантия точности или скорости для произвольного текста.

Ручная проверка смысла выявила ограничения: на вопрос о неизвестном имени питомца модель назвала собственного вымышленного кота вместо признания отсутствия сведений; при знакомстве повторно спросила уже указанную страну; на вопрос об оплате картой ответила неестественно. При этом она вспомнила страну в последующем ходе, повторила заказанный напиток и сохранила предмет разговора в магазине. Ответ C1 был сложнее и подробнее A1, но не содержал требуемого следующего вопроса. Поэтому полная проверка качества диалога не пройдена. Реализация подходит для демонстрации интеграции и ограниченной разговорной практики; надёжность самостоятельного преподавателя не подтверждена. JSON-валидация и автономные тесты не оценивают истинность английского исправления или уместность реплики.

Для замены провайдера реализуй `LanguageModel.generate(messages) -> ModelReply` и подключи адаптер в `get_language_model`. Сервис отвечает за доступ, контекст, ошибки и транзакцию; новый адаптер должен сохранять ограничения приватности и отдавать типизированные ошибки.
