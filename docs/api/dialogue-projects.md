# Проекты-папки диалогов

Проект объединяет личные чаты по теме: например, «Поездка» содержит
«Аэропорт», «Отель» и «Кафе». Перенос не объединяет сообщения и контекст ИИ.

## Подготовка и доступ

Обновите зависимости и примените [миграции](../../backend/migrations/README.md)
до запуска сервера. Для новой пустой базы: `python -m alembic upgrade head`
из `backend`. Для существующей: остановка сервера, резервная копия,
проверяемый baseline и upgrade по инструкции. Перезапуск приложения
сам по себе не добавляет столбцы в старую таблицу.

Все маршруты требуют `Authorization: Bearer <access_token>`.
Токен возвращает `POST /api/v1/auth/login` с JSON `email` и `password`.
Владельца сервер берёт из токена; `user_id` передавать запрещено.
Cloudflare для папок не нужен: эти запросы идут в наш бэкенд и базу.

## Маршруты

| Запрос | Тело | Ответ |
| --- | --- | --- |
| `POST /api/v1/projects` | `{"name":"Подготовка к поездке"}` | 201, Project |
| `GET /api/v1/projects` | — | 200, массив своих Project |
| `POST /api/v1/dialogues` | `{"title":"Аэропорт","scenario":"free_chat","project_id":7}` | 201, Dialogue |
| `GET /api/v1/dialogues` | — | 200, все свои диалоги |
| `GET /api/v1/dialogues?project_id=7` | — | 200, диалоги указанной своей папки |
| `GET /api/v1/dialogues?unassigned=true` | — | 200, свои диалоги без папки |
| `PATCH /api/v1/dialogues/21/project` | `{"project_id":8}` | 200, обновлённый Dialogue |
| `PATCH /api/v1/dialogues/21/project` | `{"project_id":null}` | 200, Dialogue без папки |

Поля ответов (значения примеров демонстрационные):

```json
{
  "id": 7, "name": "Подготовка к поездке",
  "created_at": "2000-01-01T12:00:00"
}
```

```json
{
  "id": 21, "project_id": 7, "title": "Аэропорт",
  "scenario": "free_chat", "status": "active",
  "created_at": "2000-01-01T12:00:00",
  "updated_at": "2000-01-01T12:00:00"
}
```

Имя папки: 1–160 символов после удаления внешних пробелов. Одинаковые имена
разрешены, различайте папки по ID. Лишние поля запросов запрещены.
ID проекта/диалога: целое число 1–2147483647.
В POST диалога `project_id` необязателен; отсутствие или null означает
«Без проекта». Прежний запрос `{}` работает. Теперь каждый ответ
с диалогом содержит `project_id`: число или null.
В PATCH поле обязательно: `{}` даёт 422, явный null отсоединяет.

Все списки принимают `limit` 1–100 (по умолчанию 100) и `offset`
0–9223372036854775807 (по умолчанию 0). Новые ID идут первыми;
пагинация применяется после фильтра. Пустой массив — конец этой страницы.
`unassigned=false` не ограничивает выборку; для «Все» уберите оба фильтра.
Не передавайте строку `project_id=null` в URL.
`project_id` вместе с `unassigned=true` даёт 422. Чужая/отсутствующая
папка даёт 404 даже при пустой выборке.

При переносе проверяются оба владельца. Сохраняются ID, название, сценарий,
статус, сообщения, исправления и время создания сообщений; `updated_at`
может обновиться. Повторный перенос не создаёт дубликатов, сбой откатывается.

## Общение и ошибки

Отправка прежняя: `POST /api/v1/dialogues/{id}/messages` с
`{"content":"Hello!"}` возвращает 201 и `user_message` / `assistant_message`.
GET по тому же пути возвращает историю одного чата по возрастанию ID
с теми же limit/offset. После переноса используйте прежний ID диалога.
Название папки не задаёт сценарий и общую память модели.

```json
{"error":{"code":"not_found","message":"Проект не найден","field":null}}
```

- 401 `unauthorized`: нет действующего токена.
- 404 `not_found`: объект отсутствует или принадлежит другому пользователю.
  Чужой и отсутствующий объект одного типа дают одинаковый ответ.
- 422 `validation_error`: неверные поля/ID/пагинация или конфликт фильтров.

После отказа прежняя привязка диалога сохраняется.

## Пользовательский путь

1. Вход → загрузить проекты и первую страницу диалогов.
2. Создание папки → POST проекта → добавить полученный объект в список.
3. Выбор папки → GET диалогов с соответствующим фильтром.
4. Создание чата → POST с выбранным project_id или null.
5. Общение → сообщения по ID чата, блокировка повторной отправки на время запроса.
6. Перенос → PATCH → обновить затронутые списки; прежняя история доступна.

Переименование/удаление папок, вложенность, общий доступ и общая память ИИ
между чатами пока не реализованы. Не показывайте эти действия как работающие.
