# Личные диалоги с локальным ИИ

Модуль сохраняет личные диалоги и помогает практиковать английский. Ответ формирует локальная модель через заменяемый интерфейс `LanguageModel`. Модель предлагает исправленный английский текст, а сервер описывает на русском точные замены, добавления и удаления в `correction` сообщения пользователя. Если исправления нет, поле равно `null`. Это описание изменений, а не подробное объяснение грамматического правила; правильность предложенной английской фразы зависит от модели.

Сценарии: `introductions` — «Знакомство», `cafe` — «Кафе», `shop` — «Магазин». `free_chat` и неизвестные сохранённые сценарии используют общий разговорный промпт. Неизвестное название не передаётся как инструкция модели. Последний результат assessment задаёт CEFR; без результата используется A1. Логика assessment и авторизации не меняется.

## Запуск и проверка

Из `backend`, после настройки приложения:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m uvicorn linguabot.main:app --app-dir src --workers 1
```

Нужен запущенный локальный Ollama с моделью `qwen3:4b-instruct-2507-q4_K_M` и отключёнными облачными функциями (`OLLAMA_NO_CLOUD=1` в окружении процесса Ollama). Для скачивания весов: `ollama pull qwen3:4b-instruct-2507-q4_K_M`. API не скачивает модель. Настройки backend с префиксом `LLM_` описаны в [документации API](../../../../../docs/api/dialogues-ai.md). На CPU ответ может занимать значительное время; проверка небольшого набора примеров не гарантирует безошибочные объяснения. Автономные тесты с подставным ответом модели также этого не доказывают.

Открой `http://127.0.0.1:8000/docs`. Зарегистрируй отдельного тестового пользователя, выполни login, затем вставь `access_token` в **Authorize** без префикса `Bearer`. Создай диалог:

```json
{"title": "Практика в кафе", "scenario": "cafe"}
```

Отправь `{"content": "I would like a tea, please."}` в `POST /api/v1/dialogues/{dialogue_id}/messages`. Ответ 201 содержит `user_message` и `assistant_message`; обе записи уже сохранены. `GET` того же пути возвращает историю. Без локальной модели ожидается 503, история остаётся прежней; запасного фиксированного ответа нет.

## Гарантии и ограничения

- Владелец проверяется до чтения контекста, результата теста и создания клиента модели. Чужой и отсутствующий диалог возвращают одинаковый 404.
- Модель получает доверенные инструкции, нормализованный уровень, текст текущего сообщения и ограниченную историю этого диалога. Поля аккаунта/профиля и результаты теста целиком не включаются. Сам пользовательский текст может содержать введённые пользователем сведения.
- Контекст включает до 12 последних сообщений и до 4000 байт UTF-8 их текста. Старые сообщения удаляются из контекста целиком; оставшиеся идут по времени. Текущий текст передаётся целиком в пределах 4000 символов. Полная история доступна через прежнюю пагинацию.
- До завершения генерации записи и изменение `updated_at` не выполняются. После проверки ответа обе записи и время диалога фиксируются одним commit. Ошибка модели или записи откатывает весь ход.
- Одновременный ход в тот же диалог получает 409; его нужно повторить после ответа первого хода. Защита действует в одном процессе: запускай **один worker**. Для нескольких процессов потребуется координация через БД или отдельный сервис.
- Модель не получает инструменты или доступ к файлам. Промпт отделяет инструкции от недоверенных реплик; качество исправлений и устойчивость модели проверяются отдельно.

## Устройство

`repository.py` выполняет запросы без commit. `service.py` проверяет доступ, читает assessment, готовит контекст, вызывает модель и атомарно сохраняет пару. Доверенные темы находятся в `scenarios/`, общий промпт — в `ai/prompts/dialogue.py`, адаптер Ollama и его внутренняя схема `reply`/`corrected_text` — в `integrations/llm/`. `ai/feedback.py` переводит разницу текстов в русское описание изменений без свободных грамматических утверждений модели. Публичный `ModelReply(reply, correction)`, схемы API и таблицы сохранены. Новый адаптер подключается через фабрику `get_language_model`.

В серии из 30 синтетических запросов к локальной модели все решения об исправлении совпали с ожидаемыми. Ручная проверка выявила повтор уже заданного вопроса, неестественную реплику об оплате и уход от вопроса о неизвестном личном факте. Это демонстрационный вариант интеграции; полное качество преподавания и диалога не принято. Подробности и пределы проверки приведены в [документации API](../../../../../docs/api/dialogues-ai.md).

## Автономные тесты

Из `backend` в PowerShell, с отдельной SQLite:

```powershell
$previousDatabaseUrl = $env:DATABASE_URL
try {
    $env:DATABASE_URL = 'sqlite+aiosqlite:///./.venv/chat-ai-tests.db'
    .\.venv\Scripts\python.exe -m pytest -o pythonpath=src -q
} finally {
    $env:DATABASE_URL = $previousDatabaseUrl
}
```

Тесты заменяют только внешнюю границу модели: API, авторизация, assessment и хранение работают реально. Проверяются прежний контракт, изоляция владельцев, пагинация, коррекции, уровень, ограничение истории, откат сбоев и перекрывающиеся ходы. Ollama и модель для них не нужны.
